# [SWB] 버전 표시 색 개선, 분할 화면 페이지 영역 뒤로/앞으로가기 스와이프

## 1. 목표
- 목록 제목 옆 버전(`v0.1.0`)이 너무 흐려 안 보이므로 진하게 한다. 빌드 시각 말풍선은 눌러야 보이는 요소라 배경과 확실히 구분되는 색을 쓴다.
- iPad 분할 화면에서 사이트 안을 링크로 여러 번 들어간 뒤에도 뒤로 갈 수 있게, **웹 페이지 영역의 왼쪽 가장자리 스와이프**를 뒤로가기로 지원한다. 앞으로가기도 같은 방식으로 **오른쪽 가장자리 스와이프**(왼쪽으로 밀기)를 지원한다 (사용자 추가 요청).
- 범위 밖: 스와이프 중 화면이 손가락을 따라오는 인터랙티브 전환(SWB-Q5), 오른쪽 사이드바/목록 숨김/iPhone 동작 변경 (이미 화면 가장자리에서 동작한다).
- 버전: 0.1.0 -> 0.1.1 (버그 수정, SWB-Q3)

## 2. 원인 분석 (뒤로가기)
- `WebView.swift`는 `allowsBackForwardNavigationGestures = true`로 WebKit 기본 뒤로가기 제스처를 쓴다. 이 제스처는 **화면(스크린) 왼쪽 가장자리**에서 시작해야 인식된다 (UIKit의 screen-edge 방식).
- 분할 화면에서 목록이 왼쪽이면 웹 영역의 왼쪽 끝은 화면 끝이 아니라 사이드바와 경계 핸들 오른쪽이다. 화면 왼쪽 가장자리는 사이드바 위라서 웹뷰에 닿지 않고, 웹 영역의 왼쪽 끝에서 시작해도 화면 가장자리가 아니라 인식되지 않는다. 그래서 뒤로 갈 수 없다.
- 사용자의 짐작(경계 핸들의 너비 조절 드래그와 겹쳐서)은 일부만 맞다: 핸들(12pt)은 웹뷰 밖이라 웹뷰 제스처와 겹치지 않는다. 핵심 원인은 웹 영역이 화면 가장자리에 있지 않은 것이다.
- 앞으로가기도 같은 구조다: WebKit 앞으로가기는 화면 **오른쪽** 가장자리에서 시작해야 한다. 목록이 오른쪽이면 웹의 오른쪽 끝이 사이드바 옆이라 앞으로 갈 수 없다.
- 정상 동작하는 경우: iPhone(전체 화면), 목록을 숨긴 분할(웹이 전체 폭, 양쪽 모두), 목록이 왼쪽인 분할의 앞으로가기(웹의 오른쪽 끝이 화면 끝), 목록이 오른쪽인 분할의 뒤로가기(웹의 왼쪽 끝이 화면 끝). 이 경우 기존 WebKit 제스처가 그대로 동작해야 한다. **새 제스처는 웹뷰의 그쪽 끝이 화면 끝이 아닐 때만 동작**해서 이중 이동을 막는다.
- 첫 페이지(이전 페이지 없음)에서 가장자리 스와이프로 목록 복귀(SWT)는 분할 화면에서는 목록이 이미 보여서 필요 없고, 숨긴 경우만 기존 `onSwipe`가 처리한다 (SPL). 이번 계획은 이것을 건드리지 않는다.
- 전제 확인(2026-11-21): 이 맥에는 시뮬레이터에 터치를 넣을 도구(cliclick, idb 등)가 없다. 따라서 제스처 동작은 구현 때 시도하고, 시뮬레이터로 안 되면 실기기(iPad)로 확인한다 (SWB-M3). 코드 위치와 기존 제스처 구성은 `WebView.swift`의 `SiteWebView.init`(가장자리 팬 `edgePan`, `gestureRecognizerShouldBegin`)에서 확인했다.

## 3. 전체 흐름
```
SiteWebView: 기존 edgePan(화면 왼쪽 가장자리 + 첫 페이지 -> onBack)은 그대로
추가: PaneEdgePan (웹뷰 자신의 왼쪽 가장자리 24pt에서 시작한 오른쪽 스와이프 = 뒤로, 오른쪽 가장자리 24pt에서 시작한 왼쪽 스와이프 = 앞으로)
   조건: 그쪽 웹뷰 끝이 화면 끝이 아님 (분할 + 목록이 그쪽에 보임) 그리고 web.canGoBack / web.canGoForward
   끝났을 때 충분히 밀었으면 web.goBack() / web.goForward()
버전 표시: VersionLabel 글자색/굵기, 말풍선 배경색
```

## 4. 단계별 상세
### 1) 버전 표시 색 (SWB-Q1, Q4)
- `SiteListView.swift`의 `VersionLabel`: 지금 `.foregroundStyle(.secondary)`(섹션 헤더에서 더 흐려진다)를 `Color(.label).opacity(0.7)` + 굵기 `.medium`으로 바꾼다 (라이트/다크 모두 대비가 높은 쪽). 크기(`.caption`)는 그대로.
- 빌드 시각 말풍선: 배경은 진한 파랑, 글자는 흰색(SWB-Q1). `AccentColor` 에셋에는 값이 없어 시스템 파랑이 나오므로 색을 직접 지정한다(리뷰 SWB-R3). `.presentationBackground(...)`(iOS 16.4+, 배포 대상 17)로 말풍선 배경을 채우고, 글자는 10pt를 유지하되 굵기 `.medium`으로 읽기 쉽게 한다. 화살표까지 같은 색인지 시뮬레이터로 확인한다.

### 2) 페이지 영역 뒤로/앞으로가기 스와이프 (SWB-Q2, Q5)
- `WebView.swift`에 `PaneEdgePan: UIPanGestureRecognizer` 서브클래스를 둔다. `touchesBegan`에서 시작 지점을 기록하고, 시작 지점이 웹뷰 왼쪽/오른쪽 24pt 밖이거나 조건에 안 맞으면 즉시 `state = .failed`로 만들어 웹뷰의 스크롤과 링크 탭을 지연시키지 않는다 (SWB-Q2).
- 시작 조건 (뒤로): `web.canGoBack`, 웹뷰 **왼쪽** 끝의 창 좌표 x가 1pt보다 큼 (화면 가장자리에 있으면 WebKit 기본 제스처가 이미 동작하므로 이중 이동을 막는다), 시작 x가 웹뷰 왼쪽 24pt 이내.
- 시작 조건 (앞으로): `web.canGoForward`, 웹뷰 **오른쪽** 끝과 창 오른쪽 끝의 거리가 1pt보다 큼, 시작 x가 웹뷰 오른쪽 24pt 이내.
- 끝났을 때(`.ended`): 뒤로는 오른쪽으로, 앞으로는 왼쪽으로 이동량 > 80pt 또는 **그 방향의** 속도 > 500pt/s이고 가로 이동이 세로보다 크면 `web.goBack()` / `web.goForward()`. 기준값은 기존 `shouldCloseOnEdgeSwipe`(Site.swift)와 같다. 짧게 밀었다가 반대로 튕기면 이동하지 않는다 (취소로 쓸 수 있음, 리뷰 SWB-R4).
- 시작 조건 보강(리뷰 SWB-R1, R2): 새 제스처는 분할 화면에서만 켠다 (`paneSwipe` 플래그, 가로 iPhone처럼 안전 영역 때문에 웹뷰가 창 끝에서 떨어진 경우에 켜지지 않게). 가로가 우세하고 시작한 쪽의 방향이 맞을 때만 시작한다 (`paneSwipeStarts`, 방향이 틀린 드래그가 웹 콘텐츠 터치를 취소시키지 않게).
- 순수 판단 함수 `paneSwipe(startX:viewWidth:viewMinX:screenWidth:dx:dy:vx:) -> PaneSwipe?`(Site.swift, `PaneSwipe`는 `.back`/`.forward`)로 두고 `test_site.swift`로 검증한다: 양쪽 시작 x 범위, 화면 가장자리에 닿은 쪽은 거절(이중 이동 방지), 이동량/속도 기준, 방향이 맞지 않으면 거절, 세로 우세면 거절. 기존 `shouldCloseOnEdgeSwipe`의 기준값을 재사용한다.
- 웹뷰 스크롤과의 충돌: 가장자리 24pt에서 시작한 가로 우세 스와이프만 소비하므로 세로 스크롤과 페이지 안 가로 스크롤(표, 슬라이더)에는 영향이 거의 없다.
- 사이드바 너비 핸들과의 관계: 핸들은 웹뷰 밖(12pt)이라 겹치지 않는다. 핸들 바로 옆(웹 영역의 핸들 쪽 24pt)에서 시작하면 뒤로/앞으로가기, 핸들 위에서 시작하면 너비 조절이다.

## 6. 결정 사항
- **SWB-Q1** 빌드 시각 말풍선의 색 - [확정] (a) 진한 파랑 배경 + 흰 글씨 (추천안 선택). 눌러야 보이는 요소라 눈에 잘 띄고 라이트/다크 모두 대비가 높다. 기각: (b) 노란 배경 + 검정 글씨 (c) 라벨색 반전
- **SWB-Q2** 뒤로/앞으로가기 스와이프를 시작할 수 있는 영역 - [변경 2026-11-21: 사용자 요청으로 웹 영역 전체로 확대. 구분선 쪽 20pt와 화면 끝 쪽 24pt만 비우고, 시작은 가로가 세로의 2배 이상 우세, 스와이프 중 페이지가 가로 스크롤됐으면 이동하지 않음. 방향은 그대로(오른쪽으로 밀기=뒤로)] [확정, 당시] (a) 웹 영역의 좌우 가장자리 24pt 안에서 시작한 스와이프만 (추천안 선택). 페이지 안 가로 스크롤, 텍스트 선택, 핸들과 충돌이 거의 없다. 기각: (b) 웹 영역 어디서든
- **SWB-Q3** 버전을 어떻게 올릴지 - [확정] (a) 0.1.1, 버그 수정으로 본다 (추천안 선택). 버전 흐림은 표시 결함, 분할 화면에서 뒤로 갈 수 없던 것은 SPL 동작의 누락이고, 앞으로가기는 뒤로가기와 한 쌍이라 같은 수정으로 본다. 기각: (b) 0.2.0 개선
- **SWB-Q4** 버전 글자색 - [확정(기본값)] `Color(.label)` 70% + `.medium` (라이트/다크 모두 진한 쪽). 시뮬레이터로 대비를 보고 필요하면 조절한다.
- **SWB-Q5** 스와이프 중 화면이 손가락을 따라오는 효과 - [확정(기본값)] 없음 (손을 뗄 때 기준을 넘으면 `goBack()`). 인터랙티브 전환은 WebKit 비공개 영역이라 직접 구현하면 복잡하다. 지금 SWT의 목록 복귀도 같은 방식이다.
