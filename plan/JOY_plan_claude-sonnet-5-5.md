# [JOY] 플로팅 버튼 조이스틱 조작 (뒤로/앞으로, 글자 크기, 모서리 이동)

## 1. 목표
- 분할 화면 가장자리 스와이프(SWB)가 www.clien.net 같은 사이트에서 잘 안 먹으므로, 모든 페이지에 떠 있는 플로팅 버튼(FAB)으로 뒤로/앞으로를 조작한다.
- FAB의 터치 조작을 조이스틱처럼 새로 정의한다 (iPhone/iPad, 분할/전체 화면 모두):
  - 누른 채 **왼쪽**으로 약 1cm 이상 이동 후 손을 떼면 **뒤로**, **오른쪽**이면 **앞으로**.
  - 누른 채 **위**로 약 1cm 이상 이동 후 손을 떼면 **글자 크게**, **아래**면 **글자 작게** (한 번에 10%, 지금 메뉴의 A+/A-와 같다).
  - 이동했다가 원래 자리로 돌아와 손을 떼면 **아무 동작도 없고 메뉴도 열리지 않는다**. 이동 없이 짧게 탭하면 지금처럼 메뉴가 열린다.
- 기존 "드래그하면 모서리로 이동"은 위 조작과 겹치므로 방법을 바꾼다 (JOY-Q1).
- (변경 2026-11-21, 사용자 요청: 조이스틱 최소 이동을 약 1cm에서 약 0.3cm(iPhone 18pt, iPad 16pt)로, 모서리 이동 기준을 약 3cm에서 약 1.5cm(iPhone 90pt, iPad 78pt)로 줄였다. 아래 본문의 1cm/3cm는 최초 계획 값이다. 모서리 이동 거리 이상이어도 가장 가까운 모서리가 지금과 같으면 방향 동작으로 처리한다.)
- 범위 밖: 스와이프(SWB) 제거 (그대로 둔다), 조이스틱 동작의 사용자 설정(거리/방향 바꾸기), 길게 눌러 반복.
- 버전: 0.1.3 -> 0.2.0 (규칙 2: 새 조작 방식 추가)

## 2. 현재 동작과 충돌 지점 (코드 확인 2026-11-21, BrowserView.swift)
- FAB는 `Menu`이고 `simultaneousGesture(DragGesture(minimumDistance: 8))`로 드래그한다. 손을 뗄 때 `predictedEndTranslation`(튕기는 속도 반영)으로 가장 가까운 모서리로 붙인다 (UXP/PRS). 즉 **8pt만 끌어도 이동 판정**이라 새 조작과 그대로는 공존할 수 없다.
- 새 조작은 **손을 뗀 위치(실제 이동량)** 로만 판정한다. 튕기는 속도는 쓰지 않는다 (속도를 쓰면 짧게 휙 움직여도 이동/동작이 되어 오작동).
- 버튼을 끌어도 메뉴가 같이 열리지 않는 것은 UXP/PRS에서 이미 실기기로 쓰고 있다 (이번 조작은 같은 경로이므로 "원래 자리로 돌아와 손을 떼도 메뉴 안 열림"도 같은 방식으로 기대하지만, 이 환경에서는 터치를 넣을 수 없어 시험하지 못했다. JOY-M3에서 실기기로 확인하고, 열리면 `Menu` 대신 직접 탭을 판별하는 버튼으로 바꾼다).

## 3. 전체 흐름
```
FAB 누르고 끌기 (이동량 d, dx, dy)  손을 뗄 때 판정 (fabAction)
  d < 8pt                          -> 탭: 시스템 Menu가 열린다 (지금과 같음)
  최대축 이동 < 1cm                 -> 아무것도 안 함 (돌아온 경우 포함, 메뉴 안 열림)
  1cm <= 이동 < 3cm                -> 우세한 축으로: 왼쪽 뒤로 / 오른쪽 앞으로 / 위 크게 / 아래 작게
  이동 >= 3cm                       -> 모서리 이동 (JOY-Q1 결정에 따름)
끄는 동안: 버튼이 손가락을 따라가고, 지금 놓으면 일어날 일을 버튼 옆 말풍선으로 보인다
놓은 뒤: 동작 결과를 잠깐(1.2초) 말풍선으로 보인다 ("뒤로", "앞으로", "글자 130%", "더 갈 곳 없음")
```

## 4. 단계별 상세
### 1) 거리 기준 (약 1cm)
- iOS는 포인트(pt)를 쓰고 1cm의 pt는 기기마다 조금 다르다 (화면 밀도: iPhone 약 153~159 pt/inch이면 1cm = 약 60~62pt, iPad Pro 11 = 132 pt/inch이면 약 52pt). 기기 종류로 구분한 상수를 쓴다: iPhone 60pt, iPad 52pt (`joystickDistance(isPad:)`, Site.swift). 정확한 cm가 필요하면 실기기에서 조절한다 (JOY-Q3 기본값).
- 모서리 이동 기준은 1cm의 3배 (iPhone 180pt, iPad 156pt).

### 2) 판정 순수 함수 (`fabAction`, Site.swift, 테스트 대상)
- `enum FabAction { none, back, forward, zoomIn, zoomOut, move }`, `fabAction(dx:dy:joystick:move:)`:
  1. `hypot(dx, dy) >= move`이면 `.move`.
  2. 최대축 이동 `max(|dx|, |dy|) < joystick`이면 `.none` (돌아온 경우 포함).
  3. 가로가 우세(`|dx| >= |dy|`)이면 dx < 0 `.back`, dx > 0 `.forward`. 세로가 우세이면 dy < 0 `.zoomIn`, dy > 0 `.zoomOut`.
- 대각선은 더 많이 움직인 축이 이긴다.
- `test_site.swift`: 각 방향 경계(1cm 직전/직후), 돌아온 경우(작은 이동), 대각선, 모서리 이동 경계, 음수/0.

### 3) FAB 동작 (`BrowserView.swift`)
- `DragGesture(minimumDistance: 8)`의 `onChanged`에서 이동량으로 지금 판정(`fabAction`)을 미리 계산해 힌트 말풍선(`Text` 캡슐, 버튼 위쪽 모서리면 아래쪽에 표시)을 갱신한다. 힌트: "뒤로", "앞으로", "크게 N%", "작게 N%", 모서리 이동이면 "이동" (그리고 목표 모서리 자리에 얇은 원 윤곽을 보인다), 아무 일 없으면 힌트 없음.
- `onEnded`: 실제 이동량(`translation`)으로 `fabAction`을 실행한다.
  - `.back`/`.forward`: `WebCache.view(for: site).web`의 `canGoBack`/`canGoForward`이면 `goBack()`/`goForward()`, 아니면 "뒤로(앞으로) 갈 곳이 없습니다" 말풍선.
  - `.zoomIn`/`.zoomOut`: `store.setZoom(site.id, site.zoom +/- 0.1)` (범위 제한은 `SiteStore`가 이미 한다), 결과 "글자 N%" 말풍선. 이미 최대/최소면 그 값이 그대로 보인다.
  - `.move`: 놓은 위치(`center(corner) + translation`)에서 가장 가까운 모서리(`FabCorner.nearest`)로 이동한다 (JOY-Q1). 지금의 `predictedEndTranslation`(튕기는 속도)은 쓰지 않는다. 가장 가까운 모서리가 지금 모서리면 제자리.
  - `.none`: 버튼만 원래 자리로 돌아온다.
- 놓은 뒤 말풍선은 1.2초 뒤 사라진다 (`DispatchWorkItem`을 취소 가능하게 두어 연속 조작에서 이전 말풍선이 새 것을 지우지 않게 한다).
- 메뉴(탭)는 그대로 두고, 접근성(VoiceOver는 드래그 조작을 못 한다)과 발견성을 위해 "뒤로"/"앞으로" 항목을 메뉴에 추가한다 (JOY-Q4 기본값). 또한 "버튼 위치" 하위 메뉴(`Menu("버튼 위치") { ... }`)에 네 모서리(왼쪽 위, 오른쪽 위, 왼쪽 아래, 오른쪽 아래)를 두고 지금 모서리는 체크 표시한다. 고르면 `corner`가 바뀐다 (JOY-Q1, 멀리 끌기가 번거로울 때의 대안).
