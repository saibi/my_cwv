# [SNS] 교차리뷰 (codex)

## 요약

커밋 `170f2de`는 결정된 감도 범위, 기기별 저장, 거리 환산, 옵션 화면 연결을 구현했습니다. 완료 판정 전에는 1.0cm에서 버튼 바깥쪽을 잡았을 때 화면 끝 방향으로 끌 수 있는 범위를 결정하고, 최종 버전의 옵션 화면과 실기기 동작을 확인해야 합니다.

| 계획 항목 | 구현 상태 | 확인 결과 |
| --- | --- | --- |
| SNS-Q1 감도 범위, 눈금, 기본값 | 구현 | 0.2~1.0cm, 0.05cm 단위, 기본 0.3cm입니다. 계획의 `joystickCmStep` 상수는 빠졌지만 현재 슬라이더와 보정 함수의 눈금은 일치합니다. 구현 노트에 이 차이의 이유는 없습니다. |
| SNS-Q2 모서리 이동 거리 | 구현 | 설정 cm에 5를 곱한 뒤 pt로 환산하고 반올림합니다. 기본값의 iPhone 90pt, iPad 78pt가 유지됩니다. |
| SNS-Q3 기기별 저장, CSV 제외 | 구현 | 두 화면이 같은 `@AppStorage` 키를 쓰며, CSV 백업과 복원 경로에 감도 설정이 들어가지 않습니다. |
| SNS-Q4 제외 범위 | 일치 | 방향별 감도, 탭 기준 설정, 직접 입력, 연습 영역은 추가되지 않았습니다. |
| SNS-Q5 옵션 화면 | 코드 구현 | iPhone/iPad 공통 섹션에 슬라이더, 현재 cm, 기본값 복원 버튼이 있습니다. 화면 확인은 남아 있습니다. |
| SNS-Q6 감도에 따른 여백 | 부분 충족 | 모든 눈금에서 계획의 버튼 중심 기준 여백을 만족합니다. 버튼 바깥쪽에서 시작하면 화면 끝 방향 동작이 막힐 수 있습니다. SNS-R1을 참고해 주세요. |
| 버전 0.2.2 -> 0.3.0 | 소스 반영 | 같은 커밋에서 `Version.xcconfig`를 올렸습니다. 확인 가능한 시뮬레이터 산출물의 번들 버전은 0.2.2입니다. |
| SNS-M1 순수 함수 자체 검증 | 부분 충족 | 기본값, 양끝, NaN/무한대, 범위 밖, 눈금 보정, 17개 눈금의 여백 불변식을 단언합니다. 전 구간의 환산값 검증은 빠져 있습니다. SNS-R3을 참고해 주세요. |
| SNS-M2 시뮬레이터 빌드와 스크린샷 | 부분 완료 | 구현 노트에 빌드 성공 기록이 있습니다. 최종 버전의 빌드 확인과 옵션 스크린샷이 남아 있습니다. SNS-R2를 참고해 주세요. |
| SNS-M3 실기기 | 미확인 | 재시작 없는 반영, 양끝에서 네 방향 동작, 끝 방향 도달 여부는 실기기 확인이 필요합니다. 순수 함수 테스트는 화면의 터치 가능 범위를 검증하지 않습니다. |

감도 경로는 저장된 `Double`을 유한값, 범위, 눈금 순서로 보정합니다. 이번 변경에서 외부 파일, 파일명, 외부 텍스트, 네트워크 응답, subprocess 또는 외부 CLI를 새로 처리하는 경로는 발견하지 못했습니다. 대용량 입력과 인코딩 처리도 기존 CSV 경로에 그대로 있습니다.

## 지적사항

### SNS-R1. 1.0cm에서 버튼을 잡는 위치에 따라 화면 끝 방향이 막힙니다

- **분류** 결정 필요
- **심각도** 중간
- **위치** `cwv/CWV/BrowserView.swift:47`, `cwv/CWV/BrowserView.swift:61`, `cwv/CWV/Site.swift:435`, `cwv/test_site.swift:473`
- **내용** iPhone 세로 화면에서 오른쪽 모서리에 버튼을 두고 감도를 1.0cm로 설정하면, 버튼 중심은 오른쪽 끝에서 76pt 떨어지고 앞으로 동작에는 60pt가 필요합니다. 중심보다 오른쪽으로 20pt 떨어진 버튼 안쪽에서 끌기 시작하면 화면 끝까지 56pt만 움직일 수 있어 앞으로 동작이 나오지 않습니다. 같은 시작점에서 기본값은 18pt 기준에 도달할 수 있습니다. JOY 리뷰에서 알려진 시작점 제약이 SNS의 높은 감도 거리 설정에서 다시 드러납니다. 현재 테스트는 버튼 중심의 여유만 계산합니다.
- **제안** (추천) 버튼의 조이스틱 터치 영역 전체에서 설정 거리를 확보하도록 여백을 정하고, 버튼 바깥쪽에서 시작하는 경우까지 검증합니다. 버튼이 몇 pt 더 안쪽으로 들어가는 대신 잡는 위치에 관계없이 같은 거리 기준을 적용할 수 있습니다. 또는 현재 여백을 유지하고 바깥쪽에서 시작한 끌기에 한해 화면 끝까지 남은 거리로 판정 기준을 낮출 수 있습니다. 이 경우 SNS-Q6의 여백은 유지되지만 같은 감도에서도 시작 위치에 따라 판정 거리가 달라집니다.

### SNS-R2. 최종 버전의 시뮬레이터 확인과 옵션 스크린샷이 빠져 있습니다

- **분류** 확실한 문제
- **심각도** 낮음
- **위치** `plan/SNS_plan_claude-sonnet-5-5.md:55`, `impl/SNS_impl_claude-sonnet-5-5.md:33`, `cwv/Version.xcconfig:2`
- **내용** `build/sim`의 앱 바이너리에는 `joystickCm`이 들어 있지만, 번들의 `CFBundleShortVersionString`은 `0.2.2`입니다. 이 산출물을 실행하면 SNS 코드가 들어 있어도 목록 화면에는 `v0.2.2`가 표시됩니다. 번들 생성 시각이 버전 파일 수정 시각보다 앞서므로 최종 버전의 빌드 증거로 사용할 수 없습니다. 화면 조작 수단이 없었다는 구현 노트의 설명은 스크린샷 누락 사유로 타당합니다. SNS-M2의 화면 확인 기준은 여전히 미충족입니다.
- **제안** 최종 커밋으로 시뮬레이터 앱을 빌드하고 번들 버전이 `0.3.0`인지 확인합니다. iPhone/iPad에서 옵션을 열어 슬라이더, 현재 cm, 기본값 버튼이 보이는 스크린샷을 남기고, 값을 바꿨다가 복원했을 때 버튼의 활성 상태도 확인합니다.

### SNS-R3. 자체 검증이 중간 눈금의 환산 오류를 놓칩니다

- **분류** 확실한 문제
- **심각도** 낮음
- **위치** `cwv/test_site.swift:461`, `cwv/test_site.swift:466`
- **내용** 전체 눈금 루프는 최소 거리가 감소하지 않는지, 모서리 이동 거리가 약 5배인지 확인합니다. 예를 들어 iPhone의 0.40cm에서 두 기준이 `24/120pt` 대신 `25/125pt`로 잘못 계산되어도 기존 단언은 모두 통과합니다. 이 경우 슬라이더가 표시하는 값과 실제 판정 거리가 달라져도 SNS-M1의 자체 검증이 이를 잡지 못합니다.
- **제안** 기존 17개 눈금 루프에서 iPhone/iPad 각각의 최소 이동 및 모서리 이동 거리를 계획의 환산식으로 구한 기대값과 비교합니다. 기본값, 양끝, 여백 검증은 유지합니다.

## 확인하지 못한 항목

기존 `build/test_site`는 읽기 전용 환경에서 임시 CSV를 만들다가 SNS 단언에 도달하기 전에 중단됐습니다. 거리와 여백은 코드와 별도 산술 계산으로 확인했습니다. 최종 시뮬레이터 재빌드와 화면 표시, 실기기에서의 즉시 반영, 앱 재실행 후 설정 유지, 감도 양끝의 네 방향 조작과 제스처 취소 후 재조작은 확인하지 못했습니다.
