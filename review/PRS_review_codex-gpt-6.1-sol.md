# [PRS] 교차리뷰 (codex-gpt-6.1-sol)

## 요약

백업 유실 가능성과 현재 페이지 열기 오류를 먼저 수정해야 합니다. 주요 기능과 결정 사항은 대체로 구현됐지만, 저장 실패와 복원 실패 경로의 보호가 부족합니다. 개인용 앱의 사용 규모를 기준으로 검토했습니다.

| 계획 항목 | 구현 상태 | 검증 범위와 남은 사항 |
| :--- | :--- | :--- |
| PRS-M1 / Q1: CSV, 고정 ID, 기본/사용자 목록 분리 | 구현됨 | 요구된 파서 입력과 목록 병합 테스트가 있습니다. 마이그레이션의 마지막 사이트 복원은 누락됐습니다. |
| PRS-M2: 버튼 튕기기 | 구현됨 / 완료 기준 일부 미확인 | 예측 이동량을 사용합니다. 구현 노트에서도 실기기 체감 확인은 미완료입니다. |
| PRS-M3 / Q2 / Q3: Keychain 백업과 복원 | 부분 충족 | 백업 범위는 결정과 일치합니다. 시뮬레이터 복원 성공은 구현 노트에 기록됐지만, 자체 검증은 메모리 백업만 사용해 실제 Keychain 실패 경로를 다루지 않습니다. |
| PRS-M4 / Q4: 현재 페이지를 Safari로 열기 | 부분 충족 | URL 선택 함수 테스트는 있습니다. 메모리 경고 후 현재 페이지를 잘못 읽는 경로가 있습니다. 실기기 확인도 미완료입니다. |
| PRS-M5 / Q5: CSV 누락 경고와 Google 대체 | 구현됨 | 경고 스크립트와 대체 로직이 있습니다. 빌드 검증은 구현 노트의 기록이며, 자체 검증은 실제 번들 누락 경로까지 실행하지 않습니다. |

이전 저장 형식의 마이그레이션을 추가한 이유는 타당합니다. 기존 사용자 데이터를 보존하는 데 필요합니다. CSV를 동기화 그룹 안으로 옮긴 이유도 타당합니다. 다만 마이그레이션은 ID 변경에 따른 참조까지 처리해야 합니다.

CSV는 기존 URL 검증 함수를 사용합니다. 추가된 빌드 스크립트는 경로를 인용하고 고정 안내문만 출력하며, CSV 내용을 명령으로 실행하지 않습니다. 검토 범위에서 외부 텍스트로 인한 명령 실행 문제는 발견하지 못했습니다.

## 지적사항

### PRS-R1: 백업 교체 도중 기존 Keychain 백업이 유실될 수 있습니다

- **분류**: 확실한 문제
- **심각도**: 높음
- **위치**: `cwv/CWV/Backup.swift:11`
- **내용**: 저장할 때 기존 항목을 `SecItemDelete`로 삭제한 다음 `SecItemAdd`로 다시 만듭니다. 삭제 후 프로세스가 종료되거나 추가가 실패하면 기존 백업까지 사라집니다. 이후 앱을 삭제하고 재설치하면 UserDefaults도 없어 사용자 사이트를 복원할 수 없습니다. 두 호출의 결과도 무시하므로 백업 유실을 감지하지 못합니다.
- **제안**: 기존 항목은 `SecItemUpdate`로 갱신하고, `errSecItemNotFound`일 때만 추가하십시오. 실패 시 기존 백업을 보존하고 오류를 식별할 수 있게 하십시오. 실제 저장 실패 경로를 검증해야 하며, 현재 메모리 백업 테스트는 이 문제를 발견할 수 없습니다.

### PRS-R2: UserDefaults 데이터 해석 실패 시 정상 백업까지 덮어씁니다

- **분류**: 확실한 문제
- **심각도**: 높음
- **위치**: `cwv/CWV/SiteStore.swift:46`, `cwv/CWV/SiteStore.swift:59`
- **내용**: `userData`가 존재하기만 하면 `backup.load()`를 호출하지 않습니다. 예를 들어 UserDefaults에 해석 불가능한 JSON이 있고 Keychain에는 정상 백업이 있어도, 정상 백업을 시도하지 않고 이전 `sites` 데이터 또는 빈 목록을 선택합니다. 이어서 초기화 마지막의 `save()`가 그 결과로 정상 Keychain 백업을 덮어씁니다. 이전 `sites` 키가 남아 있으면 삭제했던 사이트가 되살아나고 최근 추가 사이트가 사라질 수도 있습니다.
- **제안**: 각 저장소의 데이터를 개별적으로 디코딩하고, UserDefaults 해석 실패 시 Keychain을 시도하십시오. 읽기 실패를 정상적인 빈 목록과 구분해 복구 전에 백업을 덮어쓰지 않도록 하십시오. 깨진 `userData`와 정상 백업을 함께 주입하는 회귀 검증을 추가하십시오.

### PRS-R3: 메모리 경고 후 Safari에서 현재 글 대신 기본 페이지가 열립니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/CWV/BrowserView.swift:58`, `cwv/CWV/WebView.swift:136`, `cwv/CWV/WebView.swift:159`
- **내용**: 메모리 경고가 오면 `WebCache`는 전체 캐시를 비우지만, 화면에 표시된 웹뷰는 `Coordinator`가 계속 보유합니다. 글 상세 페이지를 보는 중 이 상태에서 "Safari에서 열기"를 누르면 `WebCache.view(for:)`가 별도의 새 웹뷰를 만듭니다. 새 웹뷰의 URL은 아직 nil이거나 사이트 기본 주소이므로, 화면에서 보고 있던 글이 열리지 않습니다. PRS-Q4의 현재 페이지 조건을 충족하지 못합니다.
- **제안**: 화면에 표시 중인 `SiteWebView`의 URL을 메뉴에 전달하십시오. 주소 조회 때문에 캐시에서 새 웹뷰를 생성하지 않게 해야 합니다. 글 상세 이동 후 메모리 경고를 발생시키고 메뉴를 실행하는 검증을 추가하십시오.

### PRS-R4: 마이그레이션에서 마지막으로 연 기본 사이트의 ID를 변환하지 않습니다

- **분류**: 확실한 문제
- **심각도**: 낮음
- **위치**: `cwv/CWV/SiteStore.swift:51`, `cwv/CWV/SiteStore.swift:58`
- **내용**: 이전 기본 사이트는 임의 UUID를 사용했고, 마이그레이션 후에는 URL 기반 고정 UUID로 바뀝니다. 글자 크기는 새 ID로 옮기지만 `lastSiteID`는 이전 UUID 그대로 읽습니다. 따라서 이전 기본 사이트를 열어 둔 상태에서 앱을 덮어쓰기 설치하면 `CWVApp`의 ID 검색이 실패해 마지막 사이트가 복원되지 않습니다. 이는 앱 삭제 후 복원을 제외한 PRS-Q3의 제한과 별개입니다.
- **제안**: 이전 목록에서 `lastSiteID`에 해당하는 사이트를 찾고, 기본 사이트로 흡수되는 항목이면 새 고정 ID로 변환해 저장하십시오. 현재 마이그레이션 테스트에 이전 `lastSiteID`를 설정하고 복원된 사이트가 존재하는지 확인하십시오.

미검증: 파일 변경 금지와 읽기 전용 환경에 따라 컴파일, UserDefaults를 쓰는 자체 검증, 시뮬레이터 빌드는 재실행하지 않았습니다. 실기기 튕기기/Safari/Keychain 및 SideStore 재서명도 확인하지 못했습니다.
남은 위험: 구현 노트의 성공 기록만으로 저장 실패, 실행 중단, 메모리 경고 상황의 데이터 보존과 현재 페이지 열기를 보장할 수 없습니다.
