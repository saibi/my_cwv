# [CWV] 교차리뷰 (codex-gpt-6.1-sol)

## 요약

핵심 기능은 대부분 구현되어 있지만, 메모리 경고 이후 웹뷰 제어가 끊기는 문제와 JavaScript 대화상자 누락은 사용 전에 수정해야 합니다. Q1의 로그인 흐름 예외도 새 창 경로에서는 지켜지지 않습니다.

검토 범위는 커밋 `d7cb32c`의 변경 파일과 호출 관계이며, 개인용 iPhone 한 대 사용을 기준으로 판단했습니다. 파일은 수정하지 않았습니다.

| 계획 항목 | 구현 상태 | 검증 및 판단 |
| :--- | :--- | :--- |
| CWV-M1 웹뷰/Cloudflare/확대 | 부분 완료 | 구현 노트에 시뮬레이터 통과 기록이 있습니다. 글자 확대는 구현됐으나 원래 완료 기준인 전체 레이아웃 확대와 다릅니다 |
| CWV-M2 모델/자체 검증 | 구현 완료 | 기존 `build/test_site` 실행 결과 `test_site: OK`. URL/도메인/zoom/JSON 검증을 포함합니다 |
| CWV-M3 목록 CRUD/순서/설정/로그인 유지 | 구현됨, 검증 부족 | 저장 코드는 있으나 저장소 재생성 테스트와 실제 UI 조작/로그인 유지 검증이 없습니다 |
| CWV-M4 제스처/새로고침/메뉴/캐시 | 부분 완료 | 관련 코드는 있습니다. 메모리 경고 처리에 결함이 있고 실제 제스처 검증은 남아 있습니다 |
| CWV-M5 IPA/설치/갱신 | 부분 완료 | 기존 IPA의 `Payload/CWV.app` 구조와 스크립트 구문을 확인했습니다. SideStore 설치/갱신은 미확인입니다 |
| CWV-Q1 외부 링크/로그인 예외 | 부분 준수 | 일반 링크는 조건을 따릅니다. 새 창은 사용자 링크 여부를 구분하지 않습니다 |
| CWV-Q2 SideStore | 준비됨 | IPA 생성 스크립트와 안내가 있습니다. 사용자 확인 단계가 남았습니다 |
| CWV-Q3 목록/전체 화면 전환 | 준수 | 캐시를 통한 복귀가 구현됐으나 메모리 경고 시 수명 관리가 잘못됐습니다 |

계획 변경 중 `text-size-adjust` 채택은 가로 잘림을 피한다는 근거와 한계가 기록되어 있어 타당합니다. 다만 M1 완료 기준도 "글자 확대와 재배치"로 맞춰야 합니다. 최소 iOS 17로 변경한 이유와 테스트 컴파일 방식 변경도 타당합니다. `currentID` 분기는 웹뷰의 뒤로 제스처와 충돌을 피하는 합리적인 선택입니다.

## 지적사항

### CWV-R1 표시 중인 웹뷰도 메모리 경고 후 제어 객체를 잃습니다

- **분류**: 확실한 문제
- **심각도**: 높음
- **위치**: `cwv/CWV/WebView.swift:82`, `cwv/CWV/WebView.swift:106`
- **내용**: `views.removeAll()`은 현재 표시 중인 `SiteWebView`도 제거합니다. SwiftUI가 보유하는 것은 반환된 `WKWebView`이며, SDK 헤더상 `navigationDelegate`와 `uiDelegate`는 모두 약한 참조입니다. 따라서 `SiteWebView`를 유지하지 못합니다. 메모리 경고 후 외부 링크 처리와 새로고침 제어가 끊깁니다. 이어서 `A+`를 누르면 `updateUIView`는 캐시에 새 웹뷰를 만들고 그쪽에 확대를 적용합니다. 화면의 기존 웹뷰는 바뀌지 않아 표시된 퍼센트와 실제 글자 크기도 달라집니다.
- **제안**: `UIViewRepresentable.Coordinator`가 표시 중인 `SiteWebView`를 강하게 보유하게 하고, `updateUIView`도 같은 객체를 갱신하십시오. 캐시에서는 비활성 항목을 제거해도 됩니다. 메모리 경고 후 delegate 유지와 확대 적용을 검증하는 회귀 테스트가 필요합니다.

### CWV-R2 JavaScript 확인/입력 대화상자가 항상 취소됩니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/CWV/WebView.swift:6`
- **내용**: `WKUIDelegate`에 새 창 처리만 구현되어 있고 `alert`, `confirm`, `prompt` 처리가 없습니다. 설치된 SDK 헤더에 따르면 미구현 시 `confirm`과 `prompt`는 취소로 처리되고 `alert`는 표시 없이 확인 처리됩니다. 예를 들어 사이트가 `if (confirm("삭제하시겠습니까?")) { ... }`로 글 삭제를 구현했다면 사용자는 삭제를 승인할 수 없습니다. 입력 오류를 `alert`로 알리는 페이지에서는 실패 이유도 보이지 않습니다.
- **제안**: 세 대화상자의 delegate를 구현하여 사용자 응답을 completion handler에 전달하십시오. 외부 메시지는 일반 텍스트로 표시하고, 로컬 HTML에서 확인/취소/입력 결과를 검증하십시오.

### CWV-R3 새 창 처리에는 Q1의 로그인 흐름 예외가 없습니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/CWV/WebView.swift:69`
- **내용**: 일반 탐색은 `.linkActivated`인 외부 링크만 Safari 시트로 보내지만, `createWebViewWith`는 외부 host면 탐색 종류와 무관하게 Safari로 보냅니다. 예를 들어 로그인 버튼의 JavaScript가 `window.open("https://인증제공자/...")`를 실행하면 `.other`인 새 창 요청도 외부 시트로 빠집니다. 이는 Q1의 "사용자가 직접 누른 링크에만 적용하고 로그인 흐름은 웹뷰에 유지"와 다릅니다.
- **제안**: 새 창 처리에도 Q1과 같은 탐색 조건을 적용하십시오. `.linkActivated` 외부 링크는 Safari로 보내고, 나머지 HTTP/HTTPS 요청은 계획대로 현재 웹뷰에서 여십시오. 일반 링크/새 창/로그인 요청의 분기를 함께 검증하십시오.

### CWV-R4 외부 페이지가 사용자 클릭 없이 다른 앱 실행을 요청할 수 있습니다

- **분류**: 결정 필요
- **심각도**: 중간
- **위치**: `cwv/CWV/WebView.swift:62`
- **내용**: HTTP/HTTPS와 일부 내부 scheme을 제외한 모든 요청을 `UIApplication.shared.open`으로 전달합니다. 사용자 동작 여부나 최상위 프레임 여부를 확인하지 않습니다. 따라서 불신하는 페이지나 삽입된 프레임이 사용자 클릭 없이 커스텀 scheme으로 이동하면, 앱은 해당 URL을 운영체제에 넘깁니다. 실제 실행이나 확인창은 대상 scheme과 OS 정책에 달려 있지만, 코드에는 요청을 제한하는 경계가 없습니다.
- **제안**:
  1. `(추천)` 사용자가 직접 누른 링크에 한해 외부 scheme을 전달합니다. 일반적인 전화/메일/앱 링크를 유지하면서 자동 실행 요청을 줄입니다.
  2. 외부 scheme 요청마다 목적지를 표시하고 확인을 받습니다. 자동 리다이렉트 기반 앱 연결도 지원하지만 조작이 늘어납니다.
  3. 현재 동작을 유지하고 자동 앱 전환 허용을 명시합니다. 변경은 작지만 외부 콘텐츠가 앱 전환을 유발할 수 있습니다.

### CWV-R5 자체 검증은 저장과 웹뷰 완료 기준을 검증하지 않습니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/test_site.swift:35`, `cwv/CWV/SiteStore.swift:11`
- **내용**: 현재 검증은 `Site.swift`만 사용합니다. JSON 왕복은 확인하지만 `SiteStore`의 저장/복원은 실행하지 않습니다. 예를 들어 `save()`의 저장 키가 초기화 시 읽는 키와 달라져 재실행 때 설정이 사라져도 테스트는 통과합니다. M3의 순서/zoom/마지막 사이트 복원과 M4의 캐시 수명/탐색 정책도 검증되지 않습니다. 구현 노트의 시드 기반 화면 확인은 실제 편집과 재실행 검증을 대체하지 못합니다.
- **제안**: 격리된 UserDefaults 저장소에서 추가/수정/삭제/순서/zoom/마지막 사이트를 저장하고 새 `SiteStore`로 복원하는 테스트를 추가하십시오. 웹뷰에는 R1과 R3의 회귀 검증을 남기고, 로그인 유지와 실제 제스처는 별도 수동 검증 결과로 기록하십시오.

검증 제한: 읽기 전용 환경에서 재빌드하지 않았으며 기존 테스트 실행 파일만 실행했습니다. 실기기/Cloudflare/로그인/네트워크 장애/SideStore 설치와 갱신은 확인하지 못했습니다. 기존 IPA 구조와 `make_ipa.sh` 구문은 확인했지만 패키징 중단 후 재실행은 검증하지 않았습니다.
