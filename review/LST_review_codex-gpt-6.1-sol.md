# [LST] 교차리뷰 (codex-gpt-6.1-sol)

## 요약

핵심 저장 모델과 목록 통합은 계획에 대체로 부합합니다. 다만 CSV 백업의 복원 가능성, 파일 읽기 제한, 초기화 시 제목 캐시에 보완이 필요합니다. LST-M4는 구현 노트에도 미검증으로 남아 있어 완료로 판단할 수 없습니다.

| 계획 항목 | 구현 상태 | 검증 범위와 차이 |
| :--- | :--- | :--- |
| LST-M1 단일 목록/저장 우선순위/마이그레이션 | 대체로 구현 | 최초 생성, 재실행, CSV 변경 무시, 두 이전 형식, Keychain 대체 저장소 테스트가 있습니다. 가장 오래된 목록의 이름은 일부 변경됩니다. |
| LST-M1 삭제/초기화 | 구현, 일부 결함 | 빈 목록 재실행은 테스트합니다. 주소를 편집한 기본 항목의 초기화 시 제목 캐시 문제는 빠져 있습니다. 초기화 테스트도 변경된 글자 크기에서 시작하지 않습니다. |
| LST-M2 통합 목록/이동/삭제/빈 목록 안내 | 코드상 구현 | 구현 노트에 빌드/첫 화면 확인이 기록되어 있습니다. 편집 모드와 제스처 확인은 남아 있습니다. |
| LST-M3 CSV 왕복/입력 제한 | 부분 충족 | 제목 쉼표, 자동 이름, 줄바꿈, BOM, 잘못된 줄, 크기/인코딩/줄 수 제한 테스트가 있습니다. 중복 항목 보존과 내보내기 제한의 일관성은 빠져 있습니다. |
| LST-M4 파일 앱/iCloud Drive | 연결 구현, 완료 기준 미충족 | 실기기 저장/복원은 미검증입니다. 단위 테스트가 파일 접근이나 선택기 동작을 검증하지는 않습니다. |
| LST-Q1 확인 후 목록 교체 | 구현 | 가져올 개수/건너뛴 줄은 교체 전 확인창에 표시합니다. 계획한 교체 후 결과 알림은 없습니다. |
| LST-Q2 글자 크기 제외 | 일치 | CSV는 주소와 이름만 저장하고, 가져온 항목은 100%로 생성됩니다. |

구현 노트의 가장 오래된 목록에 대한 id 변환/기본 항목 흡수 제거는 단일 목록 목표에 맞는 변경입니다. 반면 쉼표를 `%2C`로 바꾸는 방법은 형식 충돌을 피하지만 주소 의미까지 보존하지는 못하므로 별도 결정이 필요합니다.

변경 코드에는 새 subprocess나 외부 CLI 호출이 없습니다. CSV의 UTF-8 검사와 URL 스킴 검증은 기존 순수 함수를 재사용합니다.

## 지적사항

### LST-R1 같은 주소의 여러 항목이 백업 복원 중 사라집니다

- **분류**: `결정 필요`
- **심각도**: 중간
- **위치**: `cwv/CWV/Site.swift:94`, `cwv/CWV/SiteStore.swift:82`
- **내용**: 추가/편집은 같은 주소의 여러 항목을 허용하지만, CSV 파서는 주소 기반 id로 중복을 제거합니다. 예를 들어 같은 주소를 이름 "업무용", "개인용"으로 등록하면 백업에는 둘 다 기록되지만 복원에서는 첫 항목만 남습니다. 현재 테스트는 중복 제거만 확인하고, 앱에서 만들 수 있는 목록의 왕복 보존은 확인하지 않습니다.
- **제안**:
  1. (추천) 백업 가져오기는 중복 주소를 보존하고 각 항목에 고유 id를 부여합니다. 내장 기본 목록의 중복 제거와 분리하면 기존 사용자 데이터를 유지할 수 있습니다.
  2. 앱 전체에서 중복 주소를 금지하고 기존 중복 데이터 처리 정책을 정합니다. 기존에 허용한 목록을 바꾸므로 사용자 데이터 처리 결정이 필요합니다.

### LST-R2 복원할 수 없는 파일도 백업 성공으로 표시합니다

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `cwv/CWV/Site.swift:105`, `cwv/CWV/SiteListView.swift:58`
- **내용**: 목록 추가와 내보내기에는 상한이 없지만 가져오기는 500개/1,000,000바이트를 넘으면 거부합니다. 서로 다른 주소 501개를 등록해 백업하면 성공 메시지가 나오지만, 그 파일은 앱에서 복원할 수 없습니다. 긴 이름 때문에 크기 상한을 넘는 경우도 같습니다.
- **제안**: 내보내기 전에 생성한 CSV의 항목 수와 바이트 크기를 검사하고, 복원 범위를 넘으면 저장을 시작하지 말고 이유를 알리십시오. 500개/501개와 크기 경계에서 내보내기와 가져오기의 허용 범위가 일치하는 검증을 추가하십시오.

### LST-R3 파일 크기를 확인하지 못하면 무제한으로 읽습니다

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `cwv/CWV/SiteListView.swift:102`
- **내용**: 크기 조회 실패나 값 부재를 `0`으로 처리한 뒤 `Data(contentsOf:)`로 전체 파일을 읽습니다. 파일 제공자가 크기 정보를 제공하지 않거나 조회 후 파일이 커지면, 큰 파일을 메모리에 모두 올린 뒤에야 `importCSV`가 거부합니다. 따라서 읽기 전 1MB 제한이라는 구현 노트의 설명과 달리 메모리 사용량이 제한되지 않습니다.
- **제안**: 실제 읽기도 최대 `csvImportMaxBytes + 1`바이트로 제한하고 초과하면 중단하십시오. 크기 메타데이터 검사는 빠른 거부 수단으로 유지하되, 안전성은 제한된 읽기로 보장해야 합니다. 크기를 알 수 없는 입력과 상한 초과 읽기를 검증하십시오.

### LST-R4 쉼표가 있는 주소를 백업하면서 변경합니다

- **분류**: `결정 필요`
- **심각도**: 중간
- **위치**: `cwv/CWV/Site.swift:107`
- **내용**: `https://example.com/?q=a,b`를 내보내면 `https://example.com/?q=a%2Cb`로 바뀝니다. 쉼표는 URL 예약 문자이므로 두 표현의 처리가 항상 같지는 않습니다. 원문 쿼리를 서명 검증에 사용하는 링크 등은 복원 후 실패할 수 있습니다. 구현 노트도 이를 한계로 인정하며, 테스트는 원래 주소 보존 대신 변경된 주소를 기대합니다.
- **제안**:
  1. (추천) 쉼표가 있는 URL을 손실 없이 표현하도록 인용/이스케이프 규칙을 정하고 내보내기와 공통 파서에 함께 적용합니다. 백업의 주소 보존을 충족합니다.
  2. 현재 형식을 유지하되 해당 주소가 있으면 내보내기를 거부하고 이유를 알립니다. 구현 범위는 작지만 일부 목록은 백업할 수 없습니다.

### LST-R5 주소를 바꾼 기본 항목을 초기화하면 다른 사이트 제목이 남습니다

- **분류**: `확실한 문제`
- **심각도**: 낮음
- **위치**: `cwv/CWV/SiteStore.swift:106`
- **내용**: 자동 이름인 기본 항목 A의 주소를 B로 바꾸면 id는 유지됩니다. B를 열어 제목을 저장한 뒤 초기화하면 주소는 A로 돌아가지만 `replace(with:)`는 제목 캐시를 지우지 않습니다. 목록에는 A 주소와 B 제목이 함께 표시되고 재실행 후에도 유지됩니다. 일반 편집의 `update`에는 주소 변경 시 캐시 제거가 있지만 전체 교체에는 없습니다.
- **제안**: 교체 전후 같은 id의 주소가 달라지는 항목은 제목 캐시를 제거하십시오. 주소가 같은 항목은 계획대로 캐시를 유지하고, A -> B 편집/제목 수집/초기화 회귀 검증을 추가하십시오.

### LST-R6 가장 오래된 목록을 "그대로" 옮기면서 이름을 변경합니다

- **분류**: `확실한 문제`
- **심각도**: 낮음
- **위치**: `cwv/CWV/SiteStore.swift:60`
- **내용**: 계획과 구현 노트는 가장 오래된 `sites` 목록을 그대로 사용한다고 설명하지만 실제로는 `old.map(clean)`을 적용합니다. 이름이 호스트와 같은 `mine.com` 항목은 빈 이름으로 바뀌고, 이후 페이지를 열면 표시 이름도 페이지 제목으로 바뀝니다. 현재 마이그레이션 테스트의 이름은 호스트와 달라 이 변경을 잡지 못합니다.
- **제안**: 가장 오래된 목록을 그대로 사용한다는 계획에 맞춰 이 경로에서는 `sites = old`로 옮기십시오. 호스트와 같은 명시적 이름도 보존하는 테스트를 추가하십시오.

마지막으로, 테스트와 시뮬레이터 빌드는 파일을 쓰므로 이번 읽기 전용 리뷰에서 재실행하지 않았습니다. 통과 여부는 구현 노트의 기록이며, 실기기 iCloud Drive 저장/복원, 제스처, 네트워크 실패/중단 후 재시도는 확인하지 못했습니다. 파일은 수정하지 않았습니다.
