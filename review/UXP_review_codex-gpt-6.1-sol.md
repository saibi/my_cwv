# [UXP] 교차리뷰 (codex-gpt-6.1-sol)

## 요약

핵심 구조와 UXP-Q1~Q4 결정은 구현에 반영되었습니다. 다만 광고 필터의 정상 요청 차단, FAB 접근성 이름 누락을 수정하고 미완료 검증을 마쳐야 합니다.

| 계획 항목 | 상태 | 확인 결과 |
| :--- | :--- | :--- |
| UXP-M1 광고 조사 | 충족 | 대상 DOM/도메인이 계획에 기록되어 있습니다. |
| UXP-M2 공유 글리프/아이콘 | 부분 충족 | 같은 `AppGlyph`를 사용합니다. PNG는 1024x1024이며 투명도가 없습니다. 홈 화면 비교는 미확인입니다. |
| UXP-M3 이동/저장 | 부분 충족 | 사분면 계산, 드래그, 공통 AppStorage 구현은 있습니다. 탭/드래그 공존과 재실행 복원 검증이 빠졌습니다. |
| UXP-M4 광고 숨김 | 부분 충족 | 규칙 적용 후 로드하며 실패 시 로드하는 경로도 있습니다. 실패 경로 테스트와 로그인 확인은 없습니다. |
| UXP-Q1~Q4 | 반영 | 말풍선 글리프, 모서리 스냅, 전체 공통 저장, 항상 켜짐을 구현했습니다. |
| 외부 의존성 없음 | 이탈 | 아이콘 생성 절차에 ImageMagick이 필요합니다. |

조사 결과에 따라 광고 선택자를 바꾼 이유는 타당합니다. `project.pbxproj`를 수정하지 않은 것도 기존 파일 시스템 동기화 그룹으로 설명되며, 기존 빌드 산출물에 `adblock.json`이 포함되어 있습니다. 반면 GUI 도구 부재는 제스처 검증을 못 한 이유일 뿐, 완료 기준을 충족한 근거는 아닙니다.

## 지적사항

### UXP-R1 광고 도메인 문자열이 포함된 정상 URL도 차단합니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/CWV/adblock.json:2`
- **내용**: 차단 정규식에 URL 시작점이나 호스트 경계가 없습니다. 예를 들어 정상 사이트의 `https://community.example/api/search?q=doubleclick.net` 요청도 차단 대상이 됩니다. `https://notdoubleclick.net/main.js`도 일치합니다. 해당 문자열을 검색하거나 관련 자료를 조회하면 정상 기능이 실패할 수 있으며, 차단을 끄는 UI도 없습니다. 실제 JSON의 정규식을 읽어 이 일치를 확인했습니다.
- **제안**: 필터를 HTTP/HTTPS URL의 호스트 부분에 고정하고 하위 도메인과 호스트 종료 경계를 명시하십시오. 광고 URL은 일치하고 정상 호스트의 경로/쿼리 문자열은 일치하지 않는 회귀 검증을 추가하십시오.

### UXP-R2 글리프 교체로 FAB의 접근성 이름이 사라졌습니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/CWV/BrowserView.swift:60`
- **내용**: 기존 `Text("aA")`를 텍스트가 없는 도형 뷰로 교체했지만 접근성 이름을 지정하지 않았습니다. `AppGlyph` 내부에도 접근성 설명이 없습니다. VoiceOver 사용자는 이 메뉴가 글자 크기 조절과 목록 복귀 기능을 제공한다는 의미를 레이블에서 알 수 없습니다.
- **제안**: `Menu`에 `.accessibilityLabel("글자 크기 및 목록 메뉴")`처럼 기능을 설명하는 이름을 추가하고 VoiceOver에서 확인하십시오.

### UXP-R3 자체 검증이 M3/M4 완료 기준을 확인하지 않습니다

- **분류**: 확실한 문제
- **심각도**: 중간
- **위치**: `cwv/test_site.swift:38`, `impl/UXP_impl_claude-sonnet-5-5.md:23`
- **내용**: FAB 테스트는 사분면 계산과 enum 변환만 확인합니다. `FabCorner(rawValue: "nope") == nil`은 AppStorage의 기본값 복원이나 재실행 후 위치 유지를 검증하지 않습니다. 광고 테스트도 `trigger`/`action` 키 존재만 확인하므로 WebKit이 거부하는 규칙이나 실패 후 페이지가 로드되지 않는 회귀를 잡지 못합니다. 구현 노트에도 제스처 미확인이 명시되어 있고, 규칙 컴파일 실패 시 로드와 로그인 정상 동작의 검증 기록은 없습니다.
- **제안**: 네 모서리 이동 후 탭 메뉴 동작과 앱 재실행 복원을 확인하십시오. 광고는 정상 규칙 컴파일과 잘못된 규칙에서의 페이지 로드를 검증하고, 대상 사이트 로그인 결과를 기록하십시오. 그전에는 관련 마일스톤을 부분 완료로 표시하십시오.

### UXP-R4 아이콘 재생성에 계획 밖 외부 도구가 필요합니다

- **분류**: 확실한 문제
- **심각도**: 낮음
- **위치**: `cwv/make_icon.swift:5`, `cwv/README.md:13`
- **내용**: 계획은 외부 의존성 없이 불투명 PNG를 생성하도록 정했지만, 구현은 알파 제거를 `magick` 명령에 맡깁니다. Xcode만 설치한 환경에서는 README의 재생성 명령이 마지막 단계에서 실패합니다. 구현 노트에는 이 이탈의 이유가 없습니다. 현재 커밋된 PNG 자체는 불투명합니다.
- **제안**: 이미 사용하는 AppKit/CoreGraphics에서 불투명 RGB 비트맵으로 변환해 저장하고, README의 `magick` 단계를 제거하십시오.

파일은 수정하지 않았습니다. 읽기 전용 검사로 JSON 구조, 필터 일치 사례, PNG 속성, 기존 번들의 규칙 포함 여부를 확인했습니다.

확인하지 못한 항목: 새 빌드/Swift 자체 검증 실행, 실제 제스처와 VoiceOver, 재실행 복원, 홈 화면 아이콘, 실제 광고/로그인 및 컴파일 실패 시 로드입니다. 실행 검증이 남아 있어 전체 완료 판정은 보류합니다.
