# [VER] 교차리뷰 (codex)

## 요약

버전 `0.1.0`의 단일 출처, 번들 빌드 시각, 목록의 버전 표시, 버전 관리 규칙이 구현됐습니다. 구현 전에 다른 커밋이 버전을 올리면 `m_impl`이 같은 버전을 재사용하거나 버전을 되돌릴 수 있습니다. 이 절차를 보완하고 VER-M2의 실제 화면 동작을 확인해야 합니다.

| 계획 항목 | 구현 상태 | 검증 결과 |
| :--- | :--- | :--- |
| VER-M1 / VER-Q3, Q4 | 구현 일치. Debug와 Release가 `Version.xcconfig`를 참조하고 빌드 번호는 `1`입니다. | 기존 시뮬레이터용과 실기기용 번들에서 버전 `0.1.0`, 빌드 번호 `1`, `BuildTime.txt`를 확인했습니다. 커밋에 Team ID 변경이 없습니다. 소스 변경 없는 재빌드에서의 시각 갱신은 복사본 프로젝트 실험 기록으로 확인했습니다. 실기기용 번들의 서명 신뢰 검증은 현재 환경에서 `CSSMERR_TP_NOT_TRUSTED`를 반환했습니다. |
| VER-M2 / VER-Q1, Q5 | 부분 검증. 목록 첫 행을 섹션 헤더로 바꿨습니다. 첫 사이트 행의 둥근 모서리를 보존하는 이유와 헤더 기본색을 `Color(.label)`로 덮는 이유는 타당합니다. | 구현 노트에는 iPhone과 iPad 320pt에서 제목과 버전을 확인한 기록이 있습니다. 버전 탭, 최소 240pt, 스크롤과 편집 동작은 확인되지 않았습니다. |
| VER-M3 / VER-Q2, Q6 | 문서 반영 완료. `AGENTS.md`, 세 스킬, README 및 계획 인덱스에 반영됐습니다. | `ce64637`의 문자 규칙 검사에 일치 항목이 없었습니다. 계획과 구현 사이에 버전이 바뀌는 경우의 처리 절차는 빠져 있습니다. |

새 빌드 단계는 Xcode가 지정한 출력 경로를 따옴표로 감싸고 고정된 형식으로 `date`를 호출합니다. 앱은 번들 파일을 UTF-8로 읽으며, 읽기 실패나 빈 문자열이면 버전만 표시합니다. 새 경로에는 다운로드, 사용자 제공 파일명, 외부 텍스트를 셸에 전달하는 흐름이나 네트워크 의존성이 없습니다.

기존 `test_site.swift`는 VER의 번들 값과 화면을 검증하지 않습니다. 계획대로 산출물 검사와 화면 조작을 자체 검증으로 쓰는 방식은 타당합니다. 현재 기록은 VER-M1 일부와 VER-M3을 뒷받침하며, VER-M2의 탭 동작까지 입증하지는 못합니다.

## 지적사항

### VER-R1. 계획 이후 버전이 바뀌면 이전 목표 버전을 그대로 적용합니다

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `.agents/skills/m_plan/SKILL.md:18`, `.agents/skills/m_impl/SKILL.md:21`, `AGENTS.md:46`
- **내용**: `m_plan`은 계획 시점의 버전으로 목표를 정하고, `m_impl`은 현재 버전과 대조하는 절차 없이 그 목표를 적용합니다. 두 기능이 `0.1.0 -> 0.2.0`으로 계획되면 두 번째 기능의 버전이 오르지 않습니다. 그사이 사용자가 `1.0.0`을 명시해 적용했다면, 먼저 작성한 계획을 구현할 때 `0.2.0`으로 되돌릴 수도 있습니다.
- **제안**: 구현 커밋 직전에 현재 `MARKETING_VERSION`을 계획의 시작 버전과 비교합니다. 다르면 자동 증가분을 현재 버전 기준으로 다시 계산해 계획과 구현 노트에 기록합니다. 사용자가 직접 지정한 버전과 충돌할 때는 적용 전에 확인합니다.

### VER-R2. 화면 검증이 제목 표시에서 끝났습니다

- **분류**: `확실한 문제`
- **심각도**: 중간
- **위치**: `plan/VER_plan_claude-sonnet-5-5.md:44`, `impl/VER_impl_claude-sonnet-5-5.md:35`, `cwv/CWV/SiteListView.swift:183`
- **내용**: 기록된 스크린샷은 제목 옆 버전만 확인했습니다. 예를 들어 iPhone에서 버전을 탭해도 말풍선이 열리지 않거나 화면 전체를 덮는 형태로 열리면, 현재 스크린샷은 그대로 통과합니다. iPad의 320pt 결과로는 최소 240pt에서 한 줄로 표시되는지 확인할 수 없습니다. 섹션 헤더 변경 후 빈 목록 안내, 스크롤, 순서 변경과 삭제의 실제 확인 결과도 기록에 없습니다.
- **제안**: iPhone과 iPad에서 버전을 탭해 10pt 빌드 시각 말풍선이 열리고 바깥 탭으로 닫히는지 확인합니다. iPad에서 사이드바를 240pt로 줄여 한 줄 표시를 확인하고, 빈 목록 안내와 스크롤, 편집 모드의 이동 및 삭제 결과를 구현 노트에 남깁니다.

이번 리뷰에서는 기존 번들을 읽어 값을 확인했습니다. 새 빌드와 증분 빌드 재현, 실기기 설치, 시뮬레이터 화면 조작은 수행하지 않았으며, 실기기 서명 신뢰도 독립적으로 확인하지 못했습니다. 기존 자체 검증은 임시 파일을 쓰므로 읽기 전용 리뷰에서 실행하지 않았습니다.
